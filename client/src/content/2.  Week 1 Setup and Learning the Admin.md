# 🟢 Day 1: Partner Account and Dev Store

## 1.1 Create a Shopify Partner account (free)

**Steps:**

1. Go to [**shopify.com/partners**](http://shopify.com/partners) and click **Join now**
2. Enter your **email, first name, last name and password**
3. **Verify your email** (check your inbox)
4. Fill in your profile:
    - **Business name:** The Shopifer
    - **Country** and **website** (you can skip the website for now)
    - **Primary focus:** building stores or themes for clients
5. **Turn on two-step authentication** in your account security settings. **Do this from day one**, because you’ll be logging into client stores later.

## 1.2 Create the dev store

**Option A: Dev Dashboard (recommended for beginners)**

1. Log in to [**dev.shopify.com/dashboard**](http://dev.shopify.com/dashboard)
2. Click **Stores** in the left sidebar
3. Click **Create store** and choose **Dev** as the store type
4. **Store name:** `solenne-demo` (this becomes `solenne-demo.myshopify.com`; if the name is taken, try `solenne-demo-1`)
5. **Plan:** choose **Basic**, because most small clients are on Basic, so you’ll learn the same limits they have
6. **Feature preview:** leave this **off**. Stores with a feature preview enabled can’t use domains.
7. **Demo/test data:** **leave it off**, because you’ll add your own products
8. Click **Create store** and log in to the store

**Option B: Shopify CLI (optional, if you already have Node.js installed)**

```bash
shopify store create dev --name solenne-demo --plan basic --country US
```

## 1.3 What dev stores can and can’t do

| ✅ Can | ❌ Can’t |
| --- | --- |
| **Free**, and you’re automatically the owner | Take real payments or real orders |
| **Unlimited test orders** | Remove the password page |
| Install themes and free apps | Show a *custom* password page to visitors (you can still customize and preview it) |
| Up to 250 dev stores per organization | Be converted into a live production store |
| Work with Shopify CLI and GitHub | **Be transferred to a client** |

**What this means for you:** SOLENNE is a **portfolio and learning store only.** To show it to someone, share the link and the password.

# 🟢 Day 3: Theme — Install Ritual and Make a Backup

## 3.1 Understand the Horizon family

- Horizon is **one theme codebase with 10 presets:** Horizon, Atelier, Dwell, Fabric, Heritage, Pitch, Ritual, Savor, Tinker and Vessel
- They share the **same code**. Only the starting settings, fonts and demo layouts differ.
- **Current version:** Horizon’s release notes list **version 4.2.0** (RTL language support and bug fixes). **Palettes arrived in 4.0.**
- **Worth knowing:** Horizon’s Theme Store rating is **only about 35% positive**. Merchants report issues such as variant display glitches and hero images being cropped on some screens. **That’s good news for you:** these are exactly the problems merchants pay developers to fix.

## 3.2 Install Ritual

**Steps:**

1. Go to **Online Store → Themes**
2. Click **Add theme** → **Explore free themes** (or go to the Theme Store)
3. Search for **“Ritual”** and open it
4. Click **Try theme** or **Add to theme library**
5. Back in **Themes**, find Ritual in the **Theme library**
6. Click the **⋯** menu → **Publish** → confirm

## 3.3 Make a backup

1. On the **published theme**, click **⋯** → **Duplicate**
2. **Rename the copy:** click ⋯ → **Rename** → `SOLENNE Backup — Week 1 (clean)`
3. **Rule:** before any big change, **duplicate first.** Shopify lets you keep up to 20 themes in the library.

## 3.4 Check the version and release notes

- On the theme card, look for the **version number**
- If you see **“Update available,”** click **View release notes**, then **Review** before updating
- **Write the version number in your log.** You’ll need it for bug hunting in Stage 2.

## 3.5 Quick look inside the theme editor (no changes yet)

Click **Customize** and find each of these:

- **The top page selector:** switch between Home, Products, Collections and Pages
- **The left sidebar:** sections and blocks. Notice that blocks can be **nested inside other blocks**.
- **The gear icon (Theme settings):** look for **Colors / Palette**, Typography, Layout and Buttons
- **The device toggle:** desktop and mobile preview
- **App embeds** (the icon in the sidebar): where apps add code to the theme

**Only look this week.** You’ll design in Week 3.

## 3.6 Check the password page

- **Online Store → Preferences → Password protection:** see the password. **Copy it into your notes.**
- Open the store in an **incognito window** and enter the password to see it the way a visitor would

# 🟢 Day 4: Admin Tour, Part 1 — Products and Collections

**Method: learn by doing.** For each area, do the practice task, then **delete** the practice data at the end of the day (Week 2 is for the real data).

## 4.1 Products

**Products → Add product.** Learn each field:

| Field | What it’s for |
| --- | --- |
| **Title** | Product name, also used in SEO and the URL |
| **Description** | Rich text (headings, lists, links) |
| **Media** | Images, video and 3D. **The first image is used as the thumbnail.** |
| **Category** | Shopify’s **standard product taxonomy**. It unlocks category metafields and helps AI shopping assistants. |
| **Price / Compare-at price** | The compare-at price shows the “was” price for sales |
| **Cost per item** | Your cost, for profit reports (customers never see it) |
| **Charge tax** | Whether tax applies |
| **Inventory: SKU, barcode, quantity** | Stock tracking |
| **Continue selling when out of stock** | Allows pre-orders or backorders |
| **Shipping: weight** | Needed for weight-based shipping rates |
| **Variants** | Options such as **size** (maximum 3 options per product) |
| **Search engine listing** | SEO title, meta description, URL handle |
| **Status** | Active / Draft |
| **Publishing** | Which sales channels show the product |
| **Product type, vendor, tags** | Used for organization and **automated collections** |
| **Theme template** | Which product template the product uses |

**Practice task:**

- ☐ Create a **“Test Product”** with 2 size variants (30 ml / 50 ml) at different prices
- ☐ Add a compare-at price to one variant
- ☐ Set a SKU and a quantity for each variant
- ☐ Set it to **Draft**, then **Active**, and view it on the storefront

## 4.2 Collections

**Products → Collections → Create collection:**

| Type | How it works | When to use it |
| --- | --- | --- |
| **Manual** | You add products one by one | Curated edits such as “Gift ideas” |
| **Automated (Smart)** | Products are added automatically based on **conditions** | Categories such as “All serums” |

**Automated conditions** can use product type, tag, vendor, price, title and more. You choose **“all conditions”** (AND) or **“any condition”** (OR).

**Practice task:**

- ☐ Create a **manual** collection “Test Manual” and add Test Product
- ☐ Create an **automated** collection “Test Auto” with the condition *tag equals `test`*
- ☐ Add the tag `test` to Test Product and **watch it appear** in the collection automatically
- ☐ Look at **sort order** options (Best selling, Price, Manual)

## 4.3 Inventory and the other main areas

- ☐ **Products → Inventory:** see stock by location
- ☐ **Settings → Locations:** look at your default location (inventory is tracked per location)
- ☐ **Customers:** create a test customer (name + email)
- ☐ **Discounts:** look at the four types: **amount off products, amount off order, buy X get Y, free shipping**

## ✅ Day 4 checklist

- ☐ Can explain every product field
- ☐ Created and edited a product with variants
- ☐ Know the difference between manual and automated collections
- ☐ An automated collection updated on its own
- ☐ Looked at Inventory, Locations, Customers and Discounts
- ☐ Wrote the key points in your log

# 🟢 Day 5: Admin Tour, Part 2 — Content, Pages, Menus and Custom Data

## 5.1 Content → Files

- This is where **all uploaded images and files** live
- **Practice:** upload one image, **copy its URL**, and **add alt text**
- **Why it matters:** in Stage 1 you’ll upload your gpt-image-2 images here

## 5.2 Online Store → Pages

- **Add page:** title, content, SEO, and **template**
- **Templates:** a page can use `page` (the default) or a custom template such as `page.contact`
- **Practice:**
    - ☐ Create a **“Test Page”**
    - ☐ Create a **“Test Contact”** page and choose the **contact** template
    - ☐ View both on the storefront

## 5.3 Content → Menus

- The default menus are **Main menu** and **Footer menu**
- **Nested items:** **drag** an item slightly to the right under another one to make it a sub-item (this is how dropdowns and mega menus work)
- **Practice:**
    - ☐ Add “Test Collections” to the Main menu, linked to Test Auto
    - ☐ Add a sub-item under it
    - ☐ Check the dropdown on the storefront **on both desktop and mobile**

## 5.4 Content → Blog posts

- Blogs hold posts; you can have more than one blog
- Just look for now. You’ll use this for ingredient articles later.

## 5.5 Content → Metaobjects (look only)

- **Metaobjects** are structured content types, such as “Ingredient” with a name, image and benefit
- **You’ll build these in Stage 3.** This week, just find where they are.

## 5.6 Settings → Custom data (metafields)

- **Metafields** are **extra fields** attached to products, collections, customers, pages and more
- **Practice:**
    - ☐ Go to **Settings → Custom data → Products → Add definition**
    - ☐ Create `Test Field` as a single-line text field
    - ☐ Open Test Product, fill in the field at the bottom of the page, and save
    - ☐ **Understand the idea:** in Week 4 you’ll show metafields on the product page through **dynamic sources**

## 5.7 Settings → Policies

- **Refund, Privacy, Terms of service, Shipping, Contact information**
- Just look at the **Create from template** option. You’ll write the real policies in Week 5.
- ⚠️ Templates **aren’t legal advice.** For client stores, the owner is responsible for having them checked.

## 5.8 Online Store → Preferences

| Setting | Purpose |
| --- | --- |
| **Homepage title + meta description** | How the homepage appears in Google |
| **Social sharing image** | The image shown when someone shares a link to the store |
| **Password protection** | Password and message |
| **Customer privacy / cookie banner** | Consent settings |
| **Spam protection** | Protects contact and newsletter forms |

# 🟢 Day 6: Checkout Basics and a Test Order

**Why this matters:** a store that looks great but **has a broken checkout is useless.** Clients notice this straight away.

## 6.1 Shipping

**Settings → Shipping and delivery:**

1. Open **General shipping rates**
2. In your country’s shipping zone, add rates:
    - **Standard:** $6 (for orders under $60)
    - **Free shipping:** $0, with the condition **order price is $60 or more**
3. Save

## 6.2 Taxes and duties

**Settings → Taxes and duties:**

- Look at how tax collection is set up **per region**
- For the demo store, the default settings are fine
- ⚠️ For real clients, **tax setup is the merchant’s responsibility**, together with their accountant

## 6.3 Markets

**Markets** (in the sidebar or under Settings, depending on your admin version):

- See your **primary market** (for example the United States)
- **Just understand the idea:** markets control **currency, language and domain for each country or region**

## 6.4 Checkout and customer accounts

- **Settings → Checkout:** contact method (email or phone), required fields, tipping, order processing
- **Settings → Customer accounts:** look at how customer accounts work

## 6.5 Payments: turn on the test gateway

**Settings → Payments:**

1. If a card payment provider is active, **deactivate it**
2. Click **See all other providers** or **Choose a provider**
3. Select **Test payment gateway** → **Activate** → **Save**

## 6.6 Place a test order

1. **Activate Test Product** and set its stock to 10
2. Open the store (in incognito, with the password) → add the product to the cart → go to checkout
3. Enter a customer email and a shipping address
4. Card details for the Test payment gateway:

| Field | Enter |
| --- | --- |
| **Name on card** | `Test payment gateway` |
| **Card number** | `1` = success · `2` = failure · `3` = error |
| **CVV** | `111` |
| **Expiry** | Any future date |
1. **Place 3 orders: one with `1`, one with `2`, one with `3`.** Watch what the customer sees in each case.

## 6.7 Check what happened after the order

- ☐ **Orders:** the successful order appears (with a “test” label) as `SOL-1001`
- ☐ **Inventory:** stock went down from 10 to 9
- ☐ **Email:** the order confirmation email arrived
- ☐ **The order page:** look at fulfillment, the timeline and the customer details
- ☐ **Fulfill the order:** mark it as fulfilled and see what changes

**Important limits in test mode:** gift cards, store credit, manual payment methods and **draft orders** can’t be tested. **Always place test orders through the storefront checkout.**

## ✅ Day 6 checklist

- ☐ Standard shipping and free shipping over $60 set up
- ☐ Looked at taxes, markets, checkout and customer accounts
- ☐ Test payment gateway turned on
- ☐ Tested success (1), failure (2) and error (3)
- ☐ Order visible with the `SOL-` prefix
