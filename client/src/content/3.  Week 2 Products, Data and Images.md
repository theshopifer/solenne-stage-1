# 📅 Week 2: Products, Data and Images (full step-by-step guide)

# **Week goal:**

All 4 products plus the bundle are fully set up, with variants, SKUs, weights, inventory, categories, tags, metafields, images, descriptions and SEO. You also place a test order that proves the bundle inventory works.

**Time needed:** about 1.5–2 hours a day for 7 days.

I checked this against the current Shopify Help Center and OpenAI docs. **Four corrections to what I told you earlier:**

- **Metafields come first.** Create the definitions before the products, so you can fill them in as you add each product.
- **`key_ingredients` should be a list of single-line text, not multi-line text.** Only single-line text (including lists), integer, decimal, true/false and metaobject reference types can be used as storefront filters, and a list also looks cleaner on the page.
- **Transparent backgrounds may not work with gpt-image-2.** OpenAI’s guide says they’re supported as a “preview,” but several API providers say transparent requests fail. **Backup plan:** generate on pure white and use Shopify’s **Remove background** tool in the media editor.
- **Image size:** Shopify says square product images look best at **2048 × 2048 px**. You can upload up to 5000 × 5000 px and 20 MB. Shopify’s CDN also resizes images and serves modern formats automatically.

## 1.3 Create the metafield definitions

**Settings → Custom data → Products → Add definition.** Create each of these:

| # | Name | Namespace and key | Type | Settings |
| --- | --- | --- | --- | --- |
| 1 | **Tagline** | `custom.tagline` | Single-line text | Max 70 characters |
| 2 | **Skin type** | `custom.skin_type` | **Single-line text, list** | **Preset choices:** Dry, Normal, Combination, Oily, Sensitive, All skin types |
| 3 | **Key ingredients** | `custom.key_ingredients` | **Single-line text, list** | — |
| 4 | **How to use** | `custom.how_to_use` | Rich text | — |
| 5 | **Size note** | `custom.size_note` | Single-line text | — |
| 6 | **Routine step** | `custom.routine_step` | Integer | Min 1, max 4 |

**For each definition:**

1. Type the **Name**. The namespace and key fill in automatically, so check they match the table.
2. Add a **Description**, for example *“Short benefit line shown under the product title.”*
3. Choose the **Type** (use “List of values” for the list types)
4. For **Skin type**, turn on **Limit to preset choices** and add the 6 choices. This prevents typos, which would otherwise break filters.
5. Turn on **Storefronts** access if it’s shown, so the theme can read the field
6. Turn on **Filtering** for **Skin type** if the option is shown
7. **Save**

**Why each field exists:**

- **Tagline:** the short benefit line under the title (Week 4)
- **Skin type:** a storefront filter (Week 5) and a product info tab
- **Key ingredients:** the “Key ingredients” tab, and later the ingredient metaobjects (Stage 3)
- **How to use:** the “How to use” tab
- **Size note:** a helpful detail near the size selector
- **Routine step:** the “Step 1 → 4” routine builder in Stage 3

## 1.4 Category metafields (explained)

- When you set a **product category** (Day 5), Shopify may show **category metafields**, which are ready-made attributes for that category
- Skin care categories may include options such as skin type or product form. **What appears depends on the category you pick.**
- **Rule:** **fill in every category metafield that appears.** They power filters, marketplaces and AI shopping assistants.
- **Keep your custom metafields as well**, because they give you full control in the theme

# 🟢 Day 2: Images, Part 1 — Brand and Packshots

## 2.1 How to use gpt-image-2

| Route | How | Sizes |
| --- | --- | --- |
| **ChatGPT (easiest)** | Paste the prompt and state the aspect ratio (square, portrait or wide) | ChatGPT picks the exact pixel size |
| **OpenAI API or Playground** | Set `size`, `quality` and `background` yourself | Exact sizes, as in the tables below |

**API size rules:** both sides must be **multiples of 16**, the long side can be at most **3×** the short side, and results are most reliable **up to 2560 × 1440**.

**Newer model versions:** OpenAI’s docs now also list **gpt-image-2.5** versions. **The same prompts work with them.**

# 🟢 Day 4: Process and Upload the Images

## 4.1 Quality check before you process anything

For every image, check:

- ☐ **Label text** is spelled correctly
- ☐ **Hands and fingers** look natural in the lifestyle images
- ☐ **No stray text**, letters or logos anywhere
- ☐ **Product shapes match** across all images (same bottle, same lid)

## 4.2 Compress and convert

**Tool:** Squoosh.app (free, runs in the browser)

1. Open the image
2. Output format: **WebP**, quality **80–85**
3. **Target size:** packshots under about **400 KB**, heroes under about **500 KB**, cards under about **200 KB**
4. Download into `/SOLENNE/final/`

**Logo:** keep it as a **PNG** with transparency. To make an SVG, use **Inkscape → Path → Trace Bitmap**.

**No transparent version?** Upload the white-background version, then in Shopify open the file → **Remove background** (Shopify Magic).

## 6.3 Edit in the brand voice (the most important step)

| ❌ Remove | ✅ Use instead |
| --- | --- |
| “Elevate your routine” | Say what it actually does |
| “Miracle,” “flawless,” “transform” | Calm, concrete words |
| “Cures,” “treats,” “heals,” “repairs damage” | “Helps skin feel…” or “looks…” |
| “Clinically proven” (with no study) | Leave it out |
| Long sentences | Short sentences, one idea each |

**⚠️ Why this matters:** cosmetic products **can’t make medical claims.** Words like “cures eczema” or “treats acne” legally make a product a drug in many countries. **Clients will value you catching this.**

# 🟢 Day 7: Bundle, Test Order and QA

## 7.1 What to know about Shopify Bundles first

| Fact | What it means for you |
| --- | --- |
| **Free, on all plans** | Supports **fixed** bundles and multipacks |
| **No mix-and-match** | For “build your own set” you need a third-party app (or Plus) |
| **A bundle can’t contain another bundle** | — |
| **The bundle gets its own separate SKU** | If a component’s SKU changes, you have to **delete and recreate** the bundle |
| **Bundle stock = the component with the lowest stock** | Calculated automatically |
| **No shipping profile of its own** | Shipping is calculated from the products inside it |
| **Doesn’t work with subscriptions or pre-orders** | — |
| **No import, export or bulk editing** | Create each bundle by hand |
| **Needs the upgraded checkout** | New and dev stores already have it |
